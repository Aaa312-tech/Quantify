# 数据契约

活跃输入由 [project.toml](../configs/project.toml)指定。快照、训练和评估必须属于同一登记范围；载入前检查SHA-256、截止日及来源身份。joblib仅用于受信任的本地快照和模型。

## 快照结构

| 字段 | 内容 |
| --- | --- |
| `meta` | 证券代码、类别、名称、行业及历史身份 |
| `raws` | 各证券按日期索引的未复权OHLC、成交量和成交额 |
| `actions` | 实际权益、除权参考、登记/支付/上市日期及来源 |
| `calendar` | 有序交易日历 |
| `panels`、`scores` | 日期×证券的历史面板与基础评分 |
| `table` | 日期、证券、资格、特征、标签及标签结束日 |
| `features` | 57列有序模型输入；历史名称转换不改变列顺序 |
| `cutoff` | 完成数据的截止日 |
| `opening_status` | 可选的日期→证券→状态映射，含带时区的 `known_at`及布尔 `suspended` |

`y1/y3/y5`、`end1/end3/end5`及 `status1/status3/status5`配套使用。训练按实际标签结束日净化样本；动量、行业排名只用同日数据。历史前缀须通过重建逐项比较，字段兼容映射集中在 `configs/archive.toml`，列名冲突时拒绝载入。

价格与成交额使用元，规范化成交量使用手；账户现金为整数分，持仓为整数股。原始来源单位另行保留：BaoStock股数转整手使用 `ROUND_HALF_UP`，不反向覆盖已有历史成交量。来源换手率与金额保留原生精度，缺失值不自动填零。

## 金融接口

现有字典格式通过所属模块的类型声明约束，不增加序列化包装或转换数值类型。

| 接口 | 所属模块 | 单位和边界 |
| --- | --- | --- |
| `Forecast` | `models` | 收盘信号的`rank`、预期收益`mu`与误差边界`margin`均为比例 |
| `AllocationAccount`、`TargetWeights` | `allocation` | NAV为元；持仓、可卖部分、应收款与目标权重为NAV比例 |
| `AllocationMarket` | `allocation` | 已知证券元数据、前日平均成交额（元）及历史收益率表 |
| `OpeningQuote` | `planning` | 开盘价为元或空值，包含带时区的行情时间及显式停牌状态 |
| `Trade`、`Receivable` | `ledger` | 成交数量为整数股，价格和成交金额为元；内部现金及应收款的`cents`为整数分 |
| `AccountSnapshot` | `accounts` | JSON现金和原始本金为元；持仓保留各批次日期，权益明细仍为原列表格式 |
| `RiskSnapshot`、`RiskDecision` | `risk` | 高水位为元，回撤及敞口为比例，观察次数为整数 |

`allocate(account, forecasts, market, *, exposure, level, ...)`按账户与市场状态接收原输入，政策参数显式传递；优化器顺序和目标函数不变。`Execution.sell/buy`接收以元表示的目标持仓价值，调用方在开盘NAV边界将目标权重换算为金额。

比赛账户创建和恢复仍要求原始本金100万元。`Ledger.initial`保留整数分本金，风险初始高水位从它取得；快照写出前核对账本本金与原账户本金相同。现金盈亏不能改写本金或重置回撤分母。通用账本的合成测试可以使用其他本金，工程迁移不扩展比赛研究范围。

## 行情与时间

完整日线在收盘后使用，纸面流程以16:00为最早可用时点。开盘执行只读当时可用的报价、前一交易日流动性、历史价格和已冻结信号，不能用当日最高、最低、收盘或全天量额判断成交。

`fetch-bars`保留每次原始响应，核对证券身份、日期、OHLC、重复记录和历史重叠。补采只针对已结束批次中失败或未请求的证券，写入新目录；来源失败、缺少目标日与历史修订分别保留。多批合并须覆盖登记股票池，不能自动换源或将失败视为停牌。

`refresh-data`只接收协议列明的来源与修订，追加父快照截止日后的行情，历史缺失保持原样。输出比较原始行情、面板、评分、非标签列与新增可观察标签；新的快照不会自动启用。旧采集元数据与新增已核验状态之间的差异由 `collection_metadata_review`绑定，不放行其他未登记变化。

已知停牌仍不证明某个开盘价或收盘估值有效。复牌卖出使用较早参考收盘价时，须覆盖全部中间停牌日、每条证据在相应开盘前已公开、参考日与最后实际收盘一致，且没有待核查除权事件；相关字段为 `reference_date`、`suspension_evidence`。新买入仍须前一交易日报价。价格刻度、流动性与估值继续独立检查。

## 特征数值

跳空因子在已收盘日计算：

```text
gap_t = (O_t / C_prev) * (M_t + D_t / C_t) - 1
```

`C_prev`为前一条实际报价收盘价，`M_t`和 `D_t`为映射到当前报价的送转股倍数及每原持股现金。消去累计缩放后计算，沿用float64运算、float32入表及平均并列排名，不添加零值阈值。现金项使用当日收盘，因此不能用于当日开盘价格参考。

缺失报价期间的多个事件按时间顺序合并到下一条实际报价，现金按各事件时的股数累计，不填补缺失K线或成交能力。精度与差异范围见[登记协议](../configs/protocols/gap_precision.json)。

## 公司行为

| 字段 | 含义 |
| --- | --- |
| `cash_pay_date` | 公告中的现金支付日 |
| `cash_available_date` | 支付日后首个已观察开盘，表示模拟可用现金时点 |
| `share_list_date` | 新增股份可上市交易日期，不能以支付日代替 |
| `ex_reference_cash_per_share`、`ex_reference_share_multiplier` | 价格参考参数，不能替代实际股东权益 |
| `distribution_review` | 已核验字段、来源哈希、页码、方法与保守可用时间 |
| `distribution_date_reviews` | 追加日期证据及父快照、事件、独立验收绑定 |

股东现金用于总回报和应收款，实际送转比例用于持股数量，除权参考值用于价格边界。现金在到账前仍有应收价值，但不可用于买入。未知支付日不以除息日替代；纯转增的现金日期为空，已知现金日期不证明送股可卖。

`cash_rounding`缺省沿用历史四舍五入；明确的 `FLOOR_TO_CENT`先汇总全部应计股数再舍去不足一分部分，之后沿用既有税额保留情景。每十股比例舍尾与账户现金舍尾不同，连续收益标签不按账户分位处理。零股分配、股息税和未解决来源冲突继续列为限制。

`LABELLED_PRIMARY_AND_STRUCTURED`表示受支持版式的逐字段核验，`MANUAL_PRIMARY_REVIEW`表示已检查全文及相关原页；两者只证明列明字段。原 `date_status`、固定记录 `id`和来源 `description`保留，不从旧描述重新解析修正后的现金金额。

自动采纳要求单一实施公告、明确日期角色、税前权益及独立来源一致。未知版式、修订、多重匹配、金额冲突单列；实施金额、历史全年金额、税后金额和除权参考不能混用。原始数字空白、否定、条件及证券角色保留。目录日期后的零点仅是回顾研究约定，不认证真实盘中发布时间。

补充日期不得覆盖已有冲突或原审查。标签、同行参考收益、目标或归一化权重发生变化时须独立登记并重训，不能因非标签特征相同而沿用旧模型。当前覆盖与缺项见[状态](status.md)，字段证据及接入范围见[条款核对](distribution_terms.md)和[权益接入](distribution_availability.md)。

## 历史状态

日线 `tradestatus/isST`仅作来源筛查，不认证历史发布时间，不能直接生成开盘状态。BaoStock范围为已选沪深股票，不覆盖北交所、ETF或全市场历史成分；ETF的同名字段不映射为股票风险警示。

核验后的 `meta[symbol].risk_warning_periods`为含起日、不含止日的区间，记录边界 `available_at`、公告哈希和明确限幅。仅有公告日期时采用次日零点的保守模拟约定；信号按16:00、开盘按09:25检查可用性。ST期间排除买入是策略约定，已有持仓仍可合法卖出。

`repair-status`先精确重建父快照，再应用全部登记事实，分开记录资格、排名及标签差异。历史名称、行业、原始行情及范围外内容保持。`historical_status_review`必须绑定当前数据哈希，解除决定不能跨快照沿用。未核验状态和上市初期例外不因局部修正而视为已认证。

## 日期化行业输入

股票 `industry_history`记录 `available_at`、目录日期、分组及来源；分组键为 `capco:<门类><两位大类代码>`。按登记约定，分类在目录日期后的首个已观察交易日00:00可用，同日多期取较晚一期。首期之前及新表遗漏时保持未知，不沿用旧类别或回填未来表。

信号读取16:00可用分类，成交限制读取执行日09:25分类。已有持仓在边界失去分类时核算失败，不虚构清仓。重分类本身不触发额外调仓，每笔买入仍检查当时行业上限；被动集中另行记录。[行业对照](industry_timing.md)区分覆盖、分类体系与历史时点的影响。

## ETF身份与敞口

ETF的类型、基准身份、已披露股票金额及完整经济敞口分别处理。`fund_history`保存披露记录，`fund_mode`绑定登记对照；载入拒绝标识丢失或冲突，通用重建和标签修补必须保留。

报告使用目录日与送出日中较晚日期之后首个已观察交易日，概要还受编制日约束。选择已知最新报告期，同期完整明细公开后替换季报，较老报告迟发不覆盖新期。来源净资产为股票敞口分母；未匹配、未披露、非股票及有符号差额分别保留，不归一化或用旧明细补齐。

基准身份用于同行比较，已披露股票代理用于组合约束。未知完整经济敞口上界保持空值；衍生品账面净额为零不证明无风险。执行器按分数计算，独立核账从来源金额重建。详细口径见[ETF接入](etf_integration.md)与[敞口记录](etf_exposures.md)。

## 来源与存档

来源采集不依赖持仓、预测或收益。分页、总数、发行人身份和完整代码清单须核对；空结果、关键词命中及下载完成不表示事实核验通过。转换停牌不等于股票停牌，公告宣告复牌不等于已观察到开盘。

新快照、模型和核验使用新路径，冻结来源、失败结果和原始哈希不改写。历史数值及逐阶段来源说明保存在[原数据契约](https://github.com/Aaa312-tech/Quantify/blob/8f3bca316bfca68fa36fb7b3506af78c0fcc146b/docs/data_contract.md)，当前缺项统一维护在[状态页](status.md)。
